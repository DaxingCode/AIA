## 修复：测试识别报 "The data couldn't be read because it is missing"（2026-07-16 晚）

  - `RecognitionTypes.swift`：`types` 改为 `[String]?`（可选，兼容云端空/缺省）。
  - `ResultConfirmView.swift`：所有 `result.types.contains(...)` 改为 `result.types ?? []` 做 nil 兼容；未命中/空类型统一显示「未识别到可记录的内容」。
  - `ContentView.swift`：错误提示更明确，区分 `DecodingError`（云端返回格式不对）与一般网络错误。

## 修复：测试识别报 "EXCEED_MAX_PAYLOAD_SIZE" 与解码错误（2026-07-16 晚）
- 现象：控制台显示 `{"code":"EXCEED_MAX_PAYLOAD_SIZE"}`，且 iOS 端报 "The data couldn't be read because it is missing"（DecodingError）。
- 根因：
  1. 原图 base64 过大，超过 CloudBase HTTP 网关请求体限制；
  2. CloudBase 网关直接返回的错误格式为 `{"code":"...","message":"..."}`，不是云函数自定义的 `{"ok":...,"error":...}`，iOS 的 `CloudResponse` 解码失败。
- 修正：
  - `RecognizeService.swift`：
    - 图片压缩改为最长边 320 + JPEG 0.5，确保 base64 很小（目标 < 50 KB）；
    - 增加 HTTP 状态码检查，非 2xx 直接抛友好错误，避免把网关错误 JSON 丢给 `CloudResponse` 解码；
    - 保留 base64 长度/前缀/云端返回打印，方便调试。
- 已同步修改 Xcode 项目目录 `/Volumes/MacBook/Workbuddy/AI助理/AIA/AIA/` 与脚手架 `/Volumes/MacBook/Workbuddy/AI助理/原生代码脚手架/iOS/` 中的对应文件。
- 待用户回 Xcode：Shift+Command+K → Command+R 运行，点「测试识别」再试。若仍提示 HTTP 非 2xx，说明 CloudBase 限制极小，需再换方案（如云存储上传或分片）。
