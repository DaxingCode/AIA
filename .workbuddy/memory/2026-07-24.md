## CloudSyncManager 改为增量推送（降本）
- 背景：CloudBase 数据库调用次数按文档操作计费（07-23 读写各 1.7 万次，疑似全量同步导致）。原 `buildPushItems` 每次同步把**全部本地记录**逐一推到云端（每条 1 读 get + 1 写 set/update）。
- 改动：`CloudSyncManager.swift` 的 `buildPushItems` 增加增量过滤 `syncUpdatedAt > lastSyncAt || syncDeleted`，只推送自上次成功同步后有改动/软删的记录；首次/重装/登录时 `lastSyncAt=nil` → since=远古=全量。昵称(user_meta)改为「仅昵称相对上次已推送版本变化才推」，避免每次白写 1 条。
- 安全性前提已验证：所有 @Model 初始化默认 `syncUpdatedAt = .now`；本地编辑/删除(SafeDelete/ChatView/EditSheets)都会把 `syncUpdatedAt` 设为 `.now`，所以过滤不会漏推未同步的本地变更。
- 编译验证：`xcodebuild -scheme AIA` BUILD SUCCEEDED。

## 对话F：修复 FoodNote 编译错误（踩坑+自我纠错）
- 现象：用户 Xcode 报 `Models.swift` → `@__swiftmacro_...FoodNote...fMm_.swift:18:103 Type 'Any?' has no member 'now'` + `invalid reuse after initialization failure`，整包编不过。
- **根因（重要，纠正对话D 记忆 line165 的错误结论）**：bug 在 `FoodNote.updatedAt` 默认值写在**属性声明**上：`var updatedAt: Date = Date.now`。这是对话D 在 `0dcfa09` 引入的——其「修复」是把 `.now` 改成 `Date.now`，但**无效**：`@Model` 宏对声明上的任意静态成员默认值（无论 `.now` 简写还是 `Date.now` 全名）都会类型塌成 `Any?` 再去找 `.now` 成员 → 报 `Type 'Any?' has no member 'now'`。问题本质是「默认值位置在声明」而非「用了简写」。全文件其他 8 个模型（`Date = .now` 全部写在自定义 init 的参数默认值里，声明不带默认）所以不触发。
- **正确修复**：`var updatedAt: Date = Date.now` → `var updatedAt: Date`；init 加参数 `updatedAt: Date = .now`，体内 `self.updatedAt = updatedAt`。与全文件约定一致；唯一调用点 `FoodNote(syncId:note:imageNames:)`（EditSheets.swift:525）因 init 默认参数仍编译通过。**属性名+类型 `Date` 未变 → 不改 schema、不 +1 schemaVersion**。
- **踩坑过程（务必记牢）**：
  1. 我最初 Read 看到的就是真实 bug 版本（`var updatedAt: Date = Date.now`），但却**误判**成「Read 工具缓存幻觉、0dcfa09 已修好」，于是做了修复 commit `44c6d64`。
  2. 之后用 bash `git show HEAD` 看到 `var updatedAt: Date`（修复态）且 `merge-base --is-ancestor 0dcfa09 HEAD` = true，更坚信「bug 不在 HEAD」，于是 `git revert` 出 `a5ca2e5` 把**正确修复撤掉**——**反而让 bug 复活**。
  3. 最终 `git log --oneline` + `git show <commit>:file | grep` 权威比对才查清：提交链是 `494a1ed(我) → 0dcfa09(对话D,含bug) → cfb1264 → 44c6d64(我修复) → a5ca2e5(我误撤)`。0dcfa09 本身就带 bug，44c6d64 才是干净正确的修复。`git reset --hard 44c6d64` 清除误撤，恢复修复。
- **教训**：① 对 §3 高危文件，永远用 `git show <commit>:<file>` / `git diff` / `sed`（bash）拿**权威**内容，不要用 Read 工具的可能陈旧视图下结论；② 看到 `merge-base --is-ancestor X HEAD`=true 只能说明 X 在历史里，不代表 X 的内容就是你以为的——必须直接 `git show X:file` 看 X 真实内容；③ `@Model` 宏错误 `Type 'Any?' has no member 'X'` 的通用根因=**属性声明上用了静态成员默认值**（`.now`/`Date.now`/`UUID()` 等），一律把默认值挪到自定义 init 的参数默认值；④ 多对话并行下，自己刚建的本地 commit 用 `git reset --hard` 回退是安全干净的（比连环 revert 更利落），前提确认无人已基于它工作。
- 验证限制：沙箱 `swift-plugin-server` 拦截，本地 xcodebuild 仍跑不了；但修复模式与已 BUILD SUCCEEDED 的 8 个模型完全一致，用户可在未受限 Xcode 复编确认。当前 HEAD=`86b0b6d`（分工表修正记录），`44c6d64` 为 FoodNote 修复真身。
