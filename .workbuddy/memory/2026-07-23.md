## 01:07 修复「工资单空商户导致整体不保存」（task #242，延伸 00:40）
- 用户反馈：已在商户填「明亚」，点保存后工资单整体没保存（4 笔全丢）。
- 根因：`RecognitionSaver.autoSave` 守卫 `guard let merchant = b.merchant, !merchant.isEmpty else { continue }` 跳过空商户账单。工资单截图云端不返商户名 → 4 笔全跳过 → `session.bills` 为空 → `ResultConfirmView.applyAndSave` 按 `editableBills[i].originalIndex` 映射到 `session.bills[i]`，下标越界全部跳过 → 整单未入库。
- 关键对齐事实：`editableBills` 由 `result.billList.enumerated()` 1:1 构建（`originalIndex=i`），`autoSave` 也从同一 `result.billList` 建 `session.bills`；两者必须同数同序，`applyAndSave` 才能逐条覆盖。空商户 `continue` 破坏了计数对齐。
- 修复（`AIA/AIA/RecognitionSaver.swift`）：
  - 金额空才 `continue`；空商户兜底为 `b.category ?? "账单"` 临时建出（`let merchant = rawMerchant.isEmpty ? (b.category ?? "账单") : rawMerchant`）。
  - `MerchantMetaStore.upsert` 增加 `!rawMerchant.isEmpty` 护栏，避免把兜底分类名（如「工资」）当商户污染映射表。
  - `applyAndSave` 无需改：用用户手填「明亚」覆盖占位商户，最终落库商户=明亚。
- 验证：`xcodebuild build -project AIA/AIA.xcodeproj -scheme AIA -destination 'iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO` → **BUILD SUCCEEDED**。
- 云端零改动、无需重部署；重新编译安装 App 即生效。
- ⚠️ 铁律更新：账单保存空商户守卫已移除——空商户允许入库（兜底分类名），仅金额为空才跳过。不要再恢复「空商户 continue」逻辑。

## 2026-07-23 09:08 支付宝账单相对日期倒推修复（commit `cf48117`）
- **用户反馈**：支付宝账单截图中的相对日期（昨天12:58、星期二19:09）被错误识别为今天日期+截图时间（2026-07-23 09:06），三笔账单全部显示同一天同一时刻。
- **根因链**：
  1. 云端视觉模型对支付宝「昨天」「星期二」等相对日期**未遵守 prompt 指令**转换为 ISO8601，原样返回中文相对字符串
  2. 客户端 `RecognitionResult.date(from:)` 只认 ISO8601 一行代码 → 解析「昨天 12:58」失败 → 返回 nil
  3. `ResultConfirmView` L674 fallback `?? .now` → 显示截图拍摄时刻（09:06）
  4. `RecognitionSaver` L152 fallback 今天零点 → 自动入库时也错
- **修复（2 文件 +105/-7 行）**：
  - **`AIA/AIA/RecognitionTypes.swift`**：`date(from:)` 从单行 ISO8601 解析升级为三层解析：
    - ISO8601 直接解析（标准格式不变）
    - 中文相对日期 `parseRelativeDateTime()`：昨天/前天/大前天→倒推 N 天；星期X/周X→找最近该 weekday；纯时间→今天；支持 HH:MM[:SS] 时间提取 + 中文时间词（中午/下午/晚上/早上）
    - 占位符保护逻辑（无占位符需求，纯正则匹配即可）
  - **`云函数/recognize/index.js`**：prompt 规则 #4 加固，新增支付宝示例：「"昨天 12:58" → "2026-07-22T12:58:00+08:00"」，明确禁止原样返回中文相对日期
- **验证**：
  - Python 模拟 12 例全绿：昨天12:58→7/22 12:58 ✅、星期二19:09→7/21 19:09 ✅、星期二17:16→7/21 17:16 ✅、前天/大前天/今天/纯时间/周五/周三 全部正确
  - xcodebuild 构建分析：`RecognitionTypes.swift` 零 error（全部 error 为 SwiftData 宏插件沙箱拦截，非代码问题）
  - ⚠️ 本次沙箱环境 SwiftData 宏插件不稳定（间歇性 Operation not permitted），需用户本地 Xcode 编译确认
- **影响范围**：所有通过 `RecognitionResult.date(from:)` 解析时间的路径均受益：
  - 截图识别确认页（ResultConfirmView）
  - 自动入库（RecognitionSaver.autoSave）
  - 聊天文本 saveFromResult（ChatView）
- **不影响的场景**：ISO8601 标准格式照常走快速路径；无时间字段时 fallback 行为不变
