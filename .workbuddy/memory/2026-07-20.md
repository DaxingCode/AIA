  - **关键 SDK 坑（AppShortcut 短语带参数）**：本 SDK 版本（iOS 26.5）`AppShortcutPhrase` 的 `StringInterpolation` 同时有 `appendInterpolation(_ token: AppShortcutPhraseToken)`（吃 `.applicationName`）与 `appendInterpolation<Value,Subject>(_ subject: Subject) where Subject: KeyPath<Intent, IntentParameter<Value>>`（吃参数）。当短语写 `\(.$phrase)` 时，`.` 被解析成 `AppShortcutPhraseToken` 的成员，报 `AppShortcutPhraseToken has no member '$phrase'`（token 重载抢占，不会回退到 keypath 重载）；`\(.phrase)` 同样被当 token 成员报 no member；`\(\._phrase)` 类型对（KeyPath<Intent,IntentParameter<String>>）但 `_phrase` 是 private 不可访问；`\(TellAIAIntent.phraseKeyPath)` 能编译，但 **appintentsmetadataprocessor 拒绝非字面参数段**（invalid segment），会导致整个 target 的 App Intents 元数据不导出、快捷指令/Siri 全失效。
    - 结论：本 SDK 在 AppShortcut 短语里**无法用字面 `\(.$phrase)` 形式嵌入参数**（token 重载与 keypath 重载冲突），metadata 处理器也只认字面参数段。✅ 最终采用**固定短语不含参数**（`"跟\(.applicationName)说"`/`"用\(.applicationName)记"`/`"让\(.applicationName)提醒"`）：编译通过 + metadata 正常导出。**代价**：纯 Siri 语音触发时，系统会先说短语再追问内容（两段式）；但通过「快捷指令」添加「跟阿宝说」动作时，动作的「内容」字段可填入文本/变量，实现**一键内联传参**（满足用户「配合快捷指令」诉求）。BUILD SUCCEEDED；真机安装成功（启动被锁屏挡住，非崩溃）。
