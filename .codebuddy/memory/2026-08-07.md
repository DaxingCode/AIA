## 聊天文字/截屏识别「周期待办」全链路修复（覆盖 daily~yearly 9 种）
问题：用户发"每年9月1号提醒我羊羊的狗证需要续签"，期望生成 repeatRule=yearly 的待办，但"每年"等周期词在整个识别链路被丢弃。

根因（4 处）：
1. `AIA/AIA/RecognitionTypes.swift` 的 `TodoPayload` 无 `repeatRule` 字段（CodingKeys 漏掉 `repeat`）。
2. `AIA/AIA/RecognitionSaver.swift:235` 建 `Reminder` 未传 `repeatRule`（默认 none）。
3. `ChatView.swift` 本地兜底 `parseTodoCreate` 只解析 title+due，无周期词提取。
4. 云端 `云函数/recognize/agentSchema.js:195` enum 仅 `['none','day','week','month']`（值错位且缺 yearly）；`index.js` 规则 #19/#12 缺 yearly。

落地修改：
- A1. `TodoPayload` 加 `repeatRule`（CodingKeys `case repeatRule = "repeat"`）。
- A2. `RecognitionSaver.processRecognition` 建 Reminder 带 `repeatRule: t.repeatRule ?? "none"`。
- A3. 新增 `ChatView.parseRepeatRule(from:)` 通用映射（每天→daily / 每周→weekly / 每两周→biweekly / 每月→monthly / 每两月→bimonthly / 每季度→quarterly / 每半年→semiannual / 每年→yearly）；`parseTodoCreate` 返回 `(title,due,repeatRule)`；调用点补 `repeatRule:` 入参。
- B1. `agentSchema.js` enum 扩为 9 值并纠正 day/week/month→daily/weekly/monthly。
- B2. `index.js` 规则 #19（截图）与 #12（chat）补 yearly 语义。
- 已打包：`云函数/recognize` 下 `bash package-recognize.sh` → `recognize-20260804b-safety.zip`（FN_VERSION 命名，含最新源码）。**需上传 CloudBase 控制台重新部署**才生效。

注：下游 `RecordsViews.createNextRepeatReminder`(4174) 已对全部 8 种周期正确生成下一条，无需改。

## Siri（TellingAIAIntent）与对话页文字/语音记录逻辑统一（路线 A）
用户选路线 A：语义统一但保底。Siri 原本旁路直接调 `RecognitionSaver.autoSave(entryOrigin:"siri")`，与对话页 `processRecognition` 两套入库逻辑、且无视设置页 pending/discard。

改动：
- `RecognitionSaver.processRecognition` 新增 `forceAutoSave: Bool = false` 参数：true 时 `saveTypes=全 known`、`pendingTypes=空`，无视设置页 pending/discard 全部自动保存（Siri「直接记一笔」保底）。
- `TellAIAIntent.perform()` 第 2 步由 `autoSave` 改为 `processRecognition(..., entryOrigin:"siri", forceAutoSave:true)`；删掉原手动 `HealthManager.saveCaloriesConsumed(session.foodCaloriesTotal)` 调用——该同步已由 `performSilentSideEffects` 在 `processRecognition` 内部完成，原写法会重复同步卡路里。
- `ChatView.parseRepeatRule` 由 `private static` 提升为 `internal static`，供 `LocalQuickParse.parseTodo` 复用。
- `LocalQuickParse.parseTodo` 补 `repeatRule`（走共享 `ChatView.parseRepeatRule`），并实现「无日期周期待办 due=今天此刻」语义（`if due==nil, rr!=nil { due=Date() }`），消除本地快析路径周期词被丢弃的缺口。

效果：Siri 文字/语音记录现与对话页同一水槽（含周期待办识别、HealthKit 同步、对话气泡插入），仅行为上因 forceAutoSave 永远入库（pending 类别在前台对话页才生效）。云端路径已支持 repeat（index.js 规则#12），本地快析现也支持。

## 待办提醒页长按拖动失效修复（方案 1）
用户反馈待办提醒页长按拖动用不了。根因：`LongPressDragView` 的 `PassthroughView.hitTest` 返回 `nil`，承载它的 view 不在 touch 响应链里，挂其上的 `UILongPressGestureRecognizer` 收不到 touch。

按方案 1 最小改动修复：
- `LongPressDragView.swift`：`PassthroughView.hitTest` 改为 `return self`（必须参与 hitTest 手势才工作）；更正旧注释「allowsHitTesting(false) 不影响手势」的错误认知。
- `RecordsViews.swift`：`todoRow` 里 `LongPressDragView` 的 `.allowsHitTesting(false)` 改为 `.allowsHitTesting(true)`。点击/左滑穿透下层 SelectableRow 仍由 `gr.cancelsTouchesInView = false` 保证，不受影响。

待实测：①长按 0.5s 能否起拖；②点击进详情是否顺畅；③左滑删除是否正常。若点击/左滑卡顿再切方案 2（每行挂原生 LongPressGesture+DragGesture）。

## 批量识别测试（47 张支付截图）本地链路两个 bug 修复

1. **星期X 分支把历史支付推到未来**：`RecognizeService.parseRelativeDateTime` 原 `(X-N+7)%7` 对"支付列表里的星期X"取的是**未来**最近那天（如周四截图的「星期六」被解析成下周六），导致 130541 的 ¥30.08 落到 2026-08-12 而非 08-05。修复：支付列表的星期X 一律是历史记录，非今天时取**最近过去**的该星期几（forwardOffset-7 得负偏移）；仅当天且 list 时刻晚于 ref 时刻才回退上周。

## 运行时 SwiftData 崩溃诊断（未根治）
日志：`SwiftData/DataUtilities.swift:85: Fatal error: Couldn't find \Bill.<computed ... (Optional<String>)> on Bill with fields [...]`。发生在 `syncAfterLogin` → `pull`（`CloudSyncManager.applyBill` 插入云端 Bill 到本地 SwiftData）时。App 能启动并打印 `[ContentView] 冷启动首拉`，说明容器初始化没崩（旧库迁移"成功"或走了内存 fallback），崩在运行时插入。

排查过程关键事实：
- `Models.swift`/`AppPersistence.swift`/`AIAMigrationPlan.swift` 曾被物理挪到 `AIA/AIAKit/`，但 git 索引与 pbxproj 仍指向旧 `AIA/AIA/`（pbxproj 对这些文件是 folder-reference 动态编译，无逐文件引用）。已 `git mv`/`git checkout` 全部移回 `AIA/AIA/`，恢复 git 与磁盘一致（中性恢复，主 App folder reference 覆盖两者）。
- `AIAMigrationPlan` 所有 `VersionedSchema`（v1~v14）的 `models` **引用外部当前 `Bill.self`**，未按 memory 约定内嵌各版本历史副本。这是 SwiftData 已知反模式：旧库升级迁移时版本快照 keypath 与运行时类 keypath 身份不匹配 → keypath 失败。但 Bill 字段自 2026-07-28(bea5743) 起未变，内嵌与否对 Bill keypath 无差异，故根因更可能是**旧数据库 schema 版本低于当前迁移链起点**，旧库缺 syncId 等后期字段，SwiftData 误判旧库也含这些字段导致读取 keypath 失败。
- 尚未 100% 定位（环境跳过 xcodebuild，无法跑真实崩溃栈）。

建议修复路径（待用户选）：
1. 最快：模拟器/真机删 App 重装，得全新 v14 库绕过旧库迁移（本地库是云端缓存，登录后 syncAfterLogin 全量重拉）。
2. 根治且保留旧数据：为各 VersionedSchema 内嵌对应版本模型副本（工作量大）；或强化 `AppPersistence.makeContainer` 在旧版本库时主动删库重建（本地可重建，云端为准）。
