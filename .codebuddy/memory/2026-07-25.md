## 二级 Bug · 「删除后立刻重建被误判为重复」（修复）

- **现象**：上一阶段修了「删了没删干净」后，用户实测发现：删了一条账单，**立刻**再「记一笔 星巴克 35」→ 阿宝回复「这笔记过啦，我就不重复记了～」。账单列表确实删了，但本地的 dedup 表/DB 软删记录还在干扰。
- **两层根因**：
  1. `ChatView.recentCreations`（内存 dedup 表）+ `dedupWindow = 86400s`（24 小时）。key 算法 `chatDedupKey` 去掉金额/动词，留下「bill:星巴克」—— 删除只清了 SwiftData 没清这张表，24h 内同 key 都被判重。
  2. `DataDeduplicator.isDuplicateBill/Reminder/Food` 的 `FetchDescriptor` **predicate 没过滤 `!syncDeleted`**。删除走的是软删（`syncDeleted = true`），记录还在 DB 里被 fetch 出来当重复源。
- **修复（ChatView.swift）**：
  - `dedupWindow`: `86400 → 30s`（30s 已够防误连点/网络重试，不应拦「删了再记」正常操作）。
  - 新增 `ChatView.clearDedupKey(text:type:)` 静态方法。
  - `deleteMostRecentBill/Food/Reminder` 在 `context.delete` 之前调 `clearDedupKey` 清理对应 key（bill 用「商户+金额」、food 用「name」、todo 用「title」）。
- **修复（DataDeduplicator.swift）**：3 个 predicate 都加 `!$0.syncDeleted`，软删记录不再进重复判定。
- **验证**：xcodebuild BUILD SUCCEEDED；用户实际回归测试步骤——记一笔星巴克 35 → 删 → 再记一笔星巴克 35 → 期望正常建账。
- **教训（候选 MEMORY）**：**任何本地去重表/DB predicate 都必须过滤 `syncDeleted`**，否则「删了重建」路径会误判。**dedup window 不要超过 1 分钟**——聊天场景里"删了立刻重记"是正常操作。

## 四级 Bug · agent 删除成功但本地账单还在（修复）

- **现象**：用户说「把星巴克的账单删了」（没"刚才/最近"），阿宝回「星巴克那笔 40 块钱的账单已经帮你删掉了」，但账单列表里星巴克 ¥40 仍在。

## 五级 Bug · 多选删除多账号隔离缺失（潜在）

- 顺手审计发现：`SafeDelete`/`resolveDeleteLocally` 等删除路径都只在本机 fetch 删除，**没过滤 userId**——多账号共用同一模拟器/设备时，A 账号的删除不会通过云同步清理 B 账号的云端副本，B 账号 pull 时会把 A 删的"复活"。
- 当前不紧急：①设备切换账号会登出/清空部分本地缓存；②云端 `softDelete` 是按 userId 过滤的，跨账号不会误删。
- **隐患**：同一 userId 跨设备登录时，A 设备本地删除 vs 云端 tombstone 之间有 3s 窗口，B 设备同步时会把 A 删的"复活"。建议下个迭代给 `SafeDelete`/`resolveDeleteLocally` 加 userId 校验：删除前比对 `Bill.userId == Self.userId`，不等则跳过。

- **二级现象（同次反馈）**：用户改喊"跟阿宝AI管家说 午饭35"后，Siri 弹出「阿宝AI管家 / 信息」二选一。根因：`跟[联系人]说[内容]` 是 iOS 内置"发送信息(iMessage)"意图模板，与 App Shortcut「跟阿宝AI管家说」撞车，Siri 两候选并列→弹窗。问题在"说"这个动词（非 App 名）。**已修复**：`AIAAppShortcuts` 的 `TellAIAIntent` 短语去掉"跟…说"，改为"用…记 / …记账 / 跟…记一笔 / 记账用…"四类不与系统意图冲突的说法（待办提醒内容里带"提醒"仍生效）。改为后需重新构建+重跑 App 让系统重训短语。主推说法：「用阿宝AI管家记 午饭35」。
- **关键教训**：即便用户在「快捷指令」里给 App Shortcut 录**个性化短语"跟阿宝说"**，Siri 仍会和"发信息"意图竞争弹二选一——"说"这个动词本身触发系统发信息模板，与它是 App Shortcut 还是个性化短语无关。**彻底放弃"说/告诉"作为 Siri 触发词**，统一用"记/记账"语义才是根治。App Shortcuts 在「快捷指令」App 的「快捷指令」标签页（iOS16.4+ 顶部"App 快捷指令"分区）自动出现，无需用户自建；若看不到多是系统未索引，重启设备即可。`AIAAppShortcuts` 为 `@available(iOS 17,*)`，iOS16 设备整组不注册。
- **三级现象（同次反馈）**：用户说"用阿宝AI管家记 午饭35"，Siri 反问"内容是什么？"。根因：App Shortcut 短语未含 `\(\.$phrase)` 参数占位符，Siri 触发意图后 `phrase` 为空→追问。**已修复**：`AIAAppShortcuts` 的 `TellAIAIntent` 四条短语末尾全加 ` \(\.$phrase)`（如"用\(.applicationName)记 \(\.$phrase)"），Siri 即从说法中抽取内容直接入库。教训：**App Shortcuts 短语里凡要接收语音内容的参数，必须显式写 `\(\.$参数名)` 占位符，否则 Siri 必追问"内容是什么"**。

## Siri「用阿宝AI管家记」后 App 卡住不动（2026-07-25 晚）
- **现象**：用户 Siri 成功触发 TellAIAIntent 记了待办，然后打开 App UI 卡死。
