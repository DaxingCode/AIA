## Siri/聊天「早餐吃苹果」记到前一天的真正根因（已修，二次定位）
- 现象：8 月 11 日早上在聊天页发「早餐吃了一个苹果」，记录落到 8 月 10 日；但发「今天早餐吃了一个苹果」就正确落在 8 月 11 日。
- 第一次误判：以为是 `AppFormat.isoDate` 默认 UTC 导致清晨跨天，已给 `isoDate` 加上海时区（该改动保留，可防御真实 UTC 跨天场景）。
- 真正根因：`RelativeDateParser.extractWeekday` 用单字「一/二/三/四/五/六/日」做 `contains` 匹配星期几，导致「一个苹果」里的「一」被当成「周一」。今天是周二（8 月 11 日），`dateForWeekday` 取「最近一个已过去的周一」→ 8 月 10 日，所以记录掉到昨天。加上「今天」会先命中「今天」分支，不会走到 weekday 解析。
- 修复：`AIA/AIA/RelativeDateParser.swift` 的 `extractWeekday` 移除单字 patterns，只保留「周一/星期一/礼拜一」等带星期前缀的词。
- 同时保留的防御：`AIAKit/AppFormat.swift` 的 `isoDate` 已设上海时区。
- 构建：`xcodebuild ... build CODE_SIGNING_ALLOWED=NO` → BUILD SUCCEEDED。
- 待用户实机复测：①「早餐吃了一个苹果」归 8 月 11 日；②「今天早餐吃了一个苹果」仍正确；③「周二吃了两个苹果」「三明治」等含数字汉字的日常词不再误识别为上周/本周某日。

## 首页整页循环滚动 bug 修复（2026-08-11 落地）
- 现象：首次进首页整页「由下往上→到顶→回底部→再循环」无限滚动，顶部公告横条一直在；今日事项气泡不自动滚、底部输入框文字在自动滚。**重装依旧**。iOS 26 设备（DXiPhone）不炸，仅 iOS 18.7.7（XS Max）炸。
- 根因：`AIBottomBar`（UIComponents.swift 680-816 行）底部输入框文案轮播用了 `.task { while !Task.isCancelled { try? await Task.sleep; withAnimation {...} } }`。iOS 18 子视图身份不稳定，`withAnimation` 改 `@State` → body 重算 → AIBottomBar 重建 → `.task` 取消又重启 → 无限叠加占满主线程，整页抖动、今日气泡停摆。

## 首页整页循环滚动 bug（第二步修复，2026-08-11）
- 第一步（已落地）：`AIBottomBar` 的 `.task { while + withAnimation }` 死循环 → 改 `Timer.onReceive`。修完后底部栏翻条、气泡轮播恢复正常，但**整页仍在循环滚动**。
- 第二步根因：`homeModulesView`（ContentView.swift 1018-1057）入场动画在 iOS 18 上被反复重播。机制：父 body 因全局 `@ObservedObject`（`health`/`global`/`sync`/`layout` 等）自然刷新而重算 → iOS 18 子视图身份不稳，`LazyVGrid` 被判消失又出现 → 旧的 `.onDisappear { animateTiles = false }` 把入场状态清掉 → 重建后 `.task` 重跑 `animateTiles = true` → 宫格从「下移20+缩小+透明」重新弹入 → 布局抖动再触发……无限循环。每次 `animateTiles` false→true 让宫格在屏幕上下跳动 = 视觉上的「整页循环滚动」。气泡/底部栏用独立 `Timer.onReceive` 不受影响，故它们正常。
- 第二步修复（3 处）：① `LazyVGrid` 加 `.id("homeModulesGrid")` 固定身份；② `.task` 加 `guard !animateTiles else { return }` 幂等守卫；③ **删除 `.onDisappear { animateTiles = false }`**（循环核心，入场动画只播一次不再重置）。
- 经验：**SwiftUI 入场动画 `.task` + `.onDisappear(重置触发态)` 的组合在 iOS 18 是雷区**——父 body 任何刷新都可能让子视图被判消失→重建→动画反复重播。正确做法：`.id` 固定身份 + 幂等守卫 + 不靠 onDisappear 重置（离开页的重置放到可导航容器层）。

## 首页整页循环（第三步根因：全局单例订阅耦合，2026-08-11 落地）
- 前两步（AIBottomBar .task 死循环、LazyVGrid 入场动画循环）已修，但用户实测**整页仍在每秒重算**（带 print 看 body 每秒重算、宫格卡牌滚动位置一起抖动）。
- 根因（第三条，架构层）：`ContentView` 根视图用 `@StateObject health`/`@ObservedObject ent`/`@ObservedObject global`/`@StateObject sync` 直接持有 4 个全局单例。这些单例会在后台持续改写 `@Published`（尤其 `HealthManager` 的 HealthKit 授权后 `refreshAll()` 一次发 11 个 HK 查询，回调密集改 `stepsToday`/`restingHeartRate` 等），任一属性变化 → `objectWillChange` → **整个 `ContentView.body` 每秒重算** → 整页循环抖动。气泡(2s)/底部栏(3s)是独立子视图自己的 Timer，本就该转，不是元凶。
- 排除项：①全局 Timer 仅 3 处（气泡2s/底部栏3s/EntitlementManager 1Hz心跳），且 1Hz 心跳只在 `proTrialActive`（10分钟 Pro 体验）为真时每秒发；用户澄清 30天免费体验(`trialActive`)开着但它是纯时间读取判断、不带 Timer 不发 objectWillChange，10分钟体验没开 → 1Hz 心跳不触发。②`CloudSyncManager` 转发 `ent.objectWillChange`，但 ent 平时静默。
- 修复（仅 `ContentView.swift`，编译通过 BUILD SUCCEEDED）：
  1. 把 `health`/`ent`/`global`/`sync` 四个声明从 `@StateObject`/`@ObservedObject` 改为 `private let` 普通强引用（单例本就全局存活，let 不影响生命周期，但**切断了视图对 `objectWillChange` 的订阅**）。使用点（`health.stepsToday`/`ent.isFullAccess`/`global.announcement`/`sync.$isSyncing`/`.onReceive(sync.$isSyncing)`）全部保持兼容，功能不变。
  2. `[weak sync]` 闭包（`coldStartSync` 0.3s 延迟调用）改 `sync.autoSyncIfEnabled(...)`（let 非 optional，无需 weak）。
  3. 健康宫格（`healthTile`）末尾加 `.onReceive(HealthManager.shared.objectWillChange) { }`——让健康宫格**局部**订阅 HealthKit 变化、仅自身随健康数据刷新，不波及整页，弥补改 let 后健康数据不再驱动整页刷新的退化。
- 经验（铁律，补进 MEMORY.md）：**首页根视图绝不要用 `@ObservedObject`/`@StateObject` 持有会后台持续改动 `@Published` 的全局单例**（HealthManager/CloudSyncManager/EntitlementManager/GlobalConfigStore 等）。需要实时刷新时，让真正消费它的**局部子视图**用 `@ObservedObject` 订阅，或用 `.onReceive(singleton.objectWillChange)` 仅刷新该子视图。根视图只保留导航/布局必需且低频变更的单例（router/quickAction/layout）。
- 验证：编译通过；真机验证需用户在 XS Max 加临时 `print("🌀 body 重算")` 于 ContentView.body 顶部，确认同步完成后无每秒重算（验证后删除）。
