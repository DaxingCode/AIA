## 对话/Siri 记饮食「具体时刻」丢失修复（2026-08-10 下午）
- **现象**：用户说「昨天 下午3点 喝了咖啡」，日期显示正确（8月9日），但时间变成 8:00。
- **根因**：`RelativeDateParser` 能解析出「下午3点→15:00」，但各入口只把日期部分（`yyyy-MM-dd`）写进 `FoodPayload.date`；`RecognitionSaver` 解析纯日期时得到 00:00 UTC，再经上海时区 +8 显示成 8:00。
- **修法**：
  1. `RelativeDateParser.parse` 返回新增 `hasTime` 标记，新增 `dateTimeOrToday(from:)` 同时给出「完整日期时间 + 是否含时刻」。`extractTime` 仅时段词兜底时 `hasTime=false`，真实数字时刻时 `hasTime=true`。
  2. 聊天食物入口（`createFoodLocally`/`createFoodFromCloud`/`routeFoodCloudThenCard`）、`createFoodLocallyFallback`、Siri 快析（`LocalQuickParse.parseFood`）改用 `dateTimeOrToday`；`hasTime==true` 时用 `AppFormat.isoLocal` 存完整 ISO 时间（如 `2026-08-09T15:00:00+08:00`），否则仍存 `yyyy-MM-dd`。
  3. `RecognitionSaver` 保存 food 时：若 `FoodPayload.date` 长度>10 则按完整 ISO 时间解析并保留时刻；若是纯日期则按 `meal` 给默认时刻（早餐8点/午餐12点/晚餐18点/夜宵22点），避免 00:00 时区漂移。
  4. `ResultRowCard.commitEntry` 同样解析 `payloadFood.date` 中的相对日期和时刻，不再硬编码 `Date()`。
- **结果**：「昨天 下午3点 喝了咖啡」现在保存为 2026-08-09 15:00；只说「昨天晚餐吃了烤鱼」会保存为 2026-08-09 18:00（晚餐默认时刻）。
- 构建：AIA + ShareExtension 两 scheme `CODE_SIGNING_ALLOWED=NO` 均 BUILD SUCCEEDED。

## 4×4 大 widget「四个宫格分别点击跳转」改造（2026-08-10 收尾）
- **需求**：点大 widget（4×4 概览）的四个宫格，分别跳账单 / 待办 / 饮食 / 健康页（之前无跳转或全跳同一处）。
- **前一轮误判（已推翻）**：曾用 `Link(destination: URL("aia://xxx"))` 包 4 张 tile。但 **widget 里 `Link` 无法多区域分别命中**——这是 Apple 硬限制：一个 widget 容器内 `.widgetURL`/`Link` 只认一个整体 URL，嵌套小 widget 的 `.widgetURL` 还会抢占点击派发，实测点哪张都跳同一个（或随机）。`Link` 方案作废。
- **正解 = iOS 17+ 交互式 widget（方案 B，`Button(intent:)`）**：
  - 新建 `AIA/AIAKit/WidgetNavIntent.swift`：`WidgetNavTarget` 枚举(bill/todo/diet/health, rawValue = aia:// host) + `OpenWidgetPageIntent: AppIntent`，`openAppWhenRun=true`，`perform()` 里 `UIApplication.shared.open(URL("aia://bill|todo|food|health"))` 触发主 App 跳转（`diet` 对应 host `food`，与 AppDelegate 约定一致）。
  - `OverviewWidget.swift`：4 张 tile 的 `Link` 全部改为 `Button(intent: OpenWidgetPageIntent(target: .bill/.todo/.diet/.health)) { ... }.buttonStyle(.plain)`，并加 `import AppIntents`。小 widget 内层 `.widgetURL` 保留（单卖时仍跳），大 widget 里被 `Button(intent:)` 覆盖。
  - **原理**：widget 的 `Button(intent:)` 点击后，系统唤醒主 App 并在主 App 进程执行 `perform()` → `openURL` → AppDelegate `openURLContexts` 分流。这是 Apple 官方唯一支持"一 widget 多区域独立点击"的方案。
  - **pbxproj 改动（AIAKit 是手动引用组，非 Folder Sync）**：① 补 `WidgetNavIntent.swift` 的 `PBXFileReference` + `PBXBuildFile` 定义 + 加入 AIAKit group children + Sources phase（UUID 段 `A1B2C3020000000000000009`/`...019`，复用 AIAKit 既有序列）。② **关闭 AIAKit 的 `BUILD_LIBRARY_FOR_DISTRIBUTION`（Debug+Release 两处改 NO）**——根因：开启 library evolution 时，AppIntent 协议要求的 `public init() {}` 在生成稳定 `.swiftinterface` 时报 `init() is unavailable`，编译失败；AIAKit 仅同工程内部动态链接、不对外发稳定 ABI，关掉完全安全。
  - 注意：`PublicInitializable`/AppIntent init 在 framework 的 library-evolution 模式下的坑，下次再在 framework 放 AppIntent 直接关 BUILD_LIBRARY_FOR_DISTRIBUTION 或挪主 App。
- 构建：AIA scheme `CODE_SIGNING_ALLOWED=NO` **BUILD SUCCEEDED**；lints 0 报错。
