## 账单识别时间显示 2027-08-01 00:00 bug（已修 2026-08-03）
- 现象：截图账单「2026年8月1日 19:42:29」识别后金额对、时间显示成 2027-08-01 00:00。
- 根因叠加：①`extractISODateTime` 的 labeledPatterns 用 `\s+` 要求日/时刻间普通空格，OCR 把空格读成全角空格(\u{3000})导致整条匹配失败、只回落纯日期「2026-08-01」丢时刻；②`BillPayload.time="2026-08-01"` 在真机 `AppFormat.isoDate` 解析失败→回落 `parseRelativeDateTime`→`buildMonthDay` 对「已过今天8/1」一律顺延 +1 年成 2027。
- 修复（RecognitionTypes.swift + RecognizeService.swift）：
  1. `buildMonthDay/extractMonthDay/extractExplicitMonthDay/parseRelativeDateTime` 新增 `allowRollforward:Bool` 参数；`date(from:)` 调用落 `allowRollforward:false` → 账单绝对日期绝不顺延年份（聊天路径仍默认 true 保未来日程语义）。
  2. labeledPatterns 与 fullPatterns 的日/时刻分隔放宽为 `软空格`+全角空格(\u{3000})+不换行(\u{00A0})，确保「2026年8月1日 19:42:29」抓到完整时刻返回带 T 的 ISO 串，从源头规避再解析链路。
- 注意：之前加的 `[OCR全文]/[时间诊断]` 临时 print 仍保留以便复测验证，确认 2027 消失后再删。

## 相机上下白边根治（绕开 fullScreenCover 托管层）（2026-08-03 追加）
- 现象：上一条「加黑色根 VC + 刷 view.window?.backgroundColor」方案在真机仍残留上下安全区白边——相机画面正常、点「使用照片」能存图触发识别，但画面上下方安全区是白的。

- 根治方案（已落地 `ImagePicker.swift`，调用点零改动）：
  1. 放弃 `fullScreenCover` 托管，改用**独立黑底临时 `UIWindow`**（`windowLevel = .statusBar + 1`、黑底、`overrideUserInterfaceStyle = .dark`）present 相机根 VC。

- 经验：UIKit 相机若经 SwiftUI `fullScreenCover` 托管，安全区白边**无法在 VC 内刷黑消除**，必须绕开托管层用独立临时 window（或改 `UIWindowScene.windows` 层级）。三层黑叠加（临时 window 黑 + 根 VC 黑 + 相机 UI 延伸安全区）才彻底。

## 相机整屏白屏修复（临时 window 缺 windowScene）（2026-08-03 追加）
- 现象：上条方案落地后打开相机**整屏白、看不到任何按钮也看不到镜头画面**（不同于之前"能看到画面但有白边"）。
- 根因：新建的临时 `UIWindow` 用 `UIWindow(frame:)` 创建且**未绑定 `UIWindowScene`**。iOS 13+ 多窗口架构下，window 必须挂载到某个 `UIWindowScene` 才参与渲染；无 scene 的 window 即使 `makeKeyAndVisible()` 也只显示空白层 → 整屏白。

- 经验（写入 MEMORY 待定，先记此处）：**任何手动创建的 `UIWindow` 都必须 `init(windowScene:)` 绑定 scene**，否则 iOS 13+ 白屏。这是 UIKit 多窗口的硬性要求。
- 验证：xcodebuild 未跑，lint 0 错误。

## 账单卡片时间显示 00:00 修复（extractISODateTime 归一化失效）（2026-08-03 追加）
- 现象：支付宝账单详情页截图，**金额对、日期对，时间恒为 00:00**。诊断日志 `[时间诊断] isoTime=2026-08-01`（纯日期，无 T 时刻），而 OCR 全文明确含「支付时间 … 2026年8月1日 19:42:29」。
- 定位文件：`AIA/AIA/RecognizeService.swift` → `extractISODateTime(_:referenceDate:)`（约 2021-2096 行）。
- **根因（两个 bug 叠加）**：
  1. **归一化结果 `t` 从未被使用**。函数开头把点号误读（`19.42.29` → `19:42:29`）归一化到局部变量 `t`，但后面三次 `tryExtractDateTime(from:using:)` 以及两栏兜底的 `text.components(separatedBy:.newlines)` **全部传的是原始 `text`**。等于归一化白做了。
  2. **归一化没处理全角冒号**。OCR 实际把 `19:42:29` 读成全角 `19：42：29`（诊断 print 肉眼难辨），而 `labeledPatterns`/`fullPatterns` 的时刻捕获组写死半角 `(\d{1,2}):(\d{2})`，全角匹配不上 → 带时刻分支整条失配 → 回落到只有年月日的第 2 个 pattern → `hasTime=false` → 返回纯日期 → 入库 00:00。
- **修复（5 处编辑）**：
  1. 2033-2035 行新增 `t = t.replacingOccurrences(of: "：", with: ":")`，放在点号归一化**之前**。
  2-4. 三处 `tryExtractDateTime(from: text, ...)` → `from: t`（labeledPatterns / fullPatterns / dateOnlyPatterns）。
  5. 两栏兜底 `let lines = text.components(...)` → `t.components(...)`（`line`/`nearby` 派生自 `lines`，改源头即可全覆盖）。
- 注：`labeledPatterns` 里标签后的分隔符本就写成 `[:：]` 兼容全角，全角转半角后走 `:` 分支，不受影响；日期部分的 `[-/.年]` 也不受冒号归一化影响。
- 预期复测：`[时间诊断] isoTime=2026-08-01T19:42:29+08:00`，卡片显示「2026年8月1日 19:42」。
- 验证：lint 0 错误（xcodebuild 未跑，改动为局部变量替换）。
- **经验**：写归一化预处理时，务必检查归一化后的变量是否真的被下游使用——`var t = text` 然后下游继续用 `text` 是极隐蔽的一类 bug，编译器不报警（`t` 有被赋值和读取，不触发 unused 警告）。另：中文 OCR 场景，**任何写死半角标点的正则都应先做全角→半角归一化**（`：；，（）` 等）。
