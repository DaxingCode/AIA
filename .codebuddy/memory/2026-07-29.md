## Invalid frame dimension（Swift Charts 退化 y 轴域）
- 健康/账单/食物页 Swift Charts 在**单点或所有值相等/全 0**时退化为 `max==min==0`，内部坐标除零→"Invalid frame dimension (negative or non-finite)"。
- **根因**：缺显式 `.chartYScale(domain:)`，Swift Charts 自动算的域遇到退化点除零。
- **修复**：UIComponents.swift 新增 `safeYDomain(_ values:[Double], fallback:) -> ClosedRange<Double>` 助手：
  - 空/非有限值 → fallback
  - max==min → pad = max(1, |max|*0.05)
  - 正常 → pad = (max-min)*0.12
- 应用到 4 个图表：WeightTrendView(:78 健康体重)、RecordsViews(:788 食物近7日)、RecordsViews(:1285 健康周步)、BillCategoryView(:56 账单周支出)。

## Update NavigationRequestObserver（NavigationLink 与 path 冲突）
- 项目原 NavigationRouter 已合并 push，但告警仍在。根因不是程序化 path 双写，而是**根栈上的闭包式 `NavigationLink { dest }` 直接通过 `$router.path` binding 同步写 path**，与 router 的 `DispatchQueue.main.async` flush 同帧 → NavigationRequestObserver 收到两次更新。
- 解决：所有推到**根 NavigationStack** 的 NavigationLink 改为 `Button + NavigationRouter.shared.navigate(.xxx)`。记录在 `ContentView.swift:11` 注释「子页面内部继续用闭包式 NavigationLink → 推各自的子 NavigationStack，无冲突」。
