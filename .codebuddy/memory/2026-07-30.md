## 白屏根因：sharedMainContext 未赋值却被强制解包
- **症状**：真机删除重装后打开白屏（实为每次启动都崩，重装只是恰好触发真机验证）。
- **根因**：上一轮把 ContentView/LoginView 注入改成 `.modelContext(Self.sharedMainContext!)`（给后台同步自动合并用），但给 `AppDelegate.sharedMainContext` 赋值的主上下文创建代码段**未真正写入** `scene(_:willConnectTo:)`，`sharedMainContext` 永远为 nil → `!` 强制解包崩溃。
- **修复**：在 `scene(_:willConnectTo:)` 取 `container` 后补上：`if let container = container { Self.sharedMainContext = ModelContext(container) }`，必须在首次 `.modelContext(Self.sharedMainContext!)` 之前完成。
- **教训**：凡 `Self.sharedMainContext!` 强制解包，都必须确保在 scene 连接时已完成赋值；新增任何用到它的分支前要确认赋值存在。
- **⚠️ 本 SDK 的 SwiftData 是 iOS 26 新版**：`ModelContext` 是**具体类**（不是协议），**不存在 `automaticallyMergesChangesFromParent` 属性**，也没有 `PersistentModelContext` 类型。`ModelContext(container)` 合法（`public init(_ container: ModelContainer)`）。上下文之间写入**自动同步/合并**，后台 `ModelContext` 落盘后首页 `@Query` 自动刷新，无需手动合并开关。不要再尝试加 `automaticallyMergesChangesFromParent` 或 `PersistentModelContext`（均编译报错）。

## 登录态自动恢复小程序绑定（重装后免手粘同步码）
- **背景/根因**：同步码 `aia_bound_user_id` 只存 **UserDefaults**，删 App 清空沙盒 → 重装后设置页"未绑定"。但登录态走 **Keychain**（`AuthManager.restoreFromKeychain` 启动恢复，跨重装保留），所以重装后登录态能恢复、绑定码丢了。
- **方案**：绑定码冗余备份到**登录账号分区**的 `aia_records` type="profile" 记录（payload 带 `miniBindCode`），与昵称 profile 同 id 但不同分区（昵称写 Self.userId=小程序分区，miniBindCode 备份写 `loginId`=登录分区，避免重登前读不到）；重装重登后 `syncAfterLogin` 的 pull 经 `applyProfile` 检出 `miniBindCode` → 写 `UserDefaults "aia_pending_mini_bind_code"` → `syncAfterLogin` 的 `Task{@MainActor}` 消费并自动 `bindMiniProgram` 完成重绑+全量重同步。
- **改动点**（CloudSyncManager.swift）：①新增 `private static func backupMiniBindCode(_ code:)`，bind 成功调 `backupMiniBindCode(c)`、unbind 调 `backupMiniBindCode(nil)`（解绑墓碑 deleted:true + 清本地 pending）；②`applyProfile` 增加 miniBindCode 处理（nonisolated 上下文须直接读 `UserDefaults aia_bound_user_id` 判断，不能访问 main-actor 隔离的 `boundMiniProgramCode` 静态属性，否则编译报 main actor-isolated 错误）；③`syncAfterLogin` 的 `Task` 标 `@MainActor` 并在 `await sync` 后消费 pending。
- **限制**：仅登录用户可自动恢复（未登录纯绑小程序场景无"跨重装稳定分区"可存备份，仍须手动重粘）；解绑会清掉云端备份避免误恢复。构建 BUILD SUCCEEDED。

## Phase 2 账号关联（跨身份提供方合并）— 后端基础已落地
- **澄清（用户 2026-07-30）**：Phase 1 同步在"同一登录方式跨设备"即生效——同一手机号、或同一 Apple ID 在 iPhone/iPad 间，userId 一致（onepass=phone_xxx / apple=apple_<iden> / wechat=wx_<keychainUUID> 均跨设备稳定），数据直接可见。Phase 2 只解决**不同登录方式之间**的合并（手机号↔Apple↔微信同步码）。
- **已做（云函数 `aia-sync/index.js`）**：新增 `aia_user_links` 集合 + `link`/`resolve`/`unlink` 三个 action（路由放在 userId 守卫之前，本身携带 primary/secondary）。
  - `resolve(rawUserId)`：查 links，返回主账号 userId；无映射/出错回落自身 → 登录必然可用。
