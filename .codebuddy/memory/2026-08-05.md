## 设置页「自动同步设置」卡死【重装后复现 + 深层根因】（2026-08-05 补充）
- 首轮 `guard isAvailable()` 修复**在重装场景失效**：模拟器 `url(forUbiquityContainerIdentifier:)` 返回**非 nil**（本地占位容器，不报错）→ `ICloudBackupManager.isAvailable()` 返回 `true`，首轮守卫完全绕过。
- 复现条件：**模拟器重装 app 后再点「自动同步设置」**（首装正常）——ubiquity 目录**不随 app 删除**，重装后 `backupDir` 残留上次备份的 `AIA.store`/-wal/-shm/附件。
- 卡死链路：残留文件 → `resumeUploadMonitorIfNeeded` 的 `collectUploadFiles` 列出 total>0 → 模拟器不真上传（status 永非 `.current`）→ `done<total` → `startUploadMonitor` 挂 **RunLoop.main 1s Timer** 每 1s 对每个残留文件同步查 `resourceValues` → **阻塞主线程** → `everDone` 永达不到 total、Timer 永不 invalidate → `icloudBusy=true` 永不复位 → **NavigationStack 转场被堵死**（表象=「按钮闪一下、不跳转、整页卡」，非点了没反应）。
- 修复（Craft 落地，重装 + Apple 登录后验证正常跳转）：
  1. `ICloudBackupManager.resumeUploadMonitorIfNeeded` 入口加 `#if targetEnvironment(simulator) return false #endif`（置于 `guard let dest=backupDir` 之前）——模拟器不真上传，残留文件不再触发主线程 Timer。
  2. `ICloudBackupManager.startUploadMonitor` Timer 回调内 `resourceValues` 查询移入 `DispatchQueue.global(qos:.utility)`，结果回主线程更新 `everDone/liveProgress`；`everDone>=total` 才 invalidate。
  3. `AutoSyncSettingsView.task` 入口加 `#if targetEnvironment(simulator) icloudAvailable=false; icloudBusy=false; return #endif`（置于 `guard ICloudBackupManager.isAvailable()` 之前）——模拟器直接走 iCloud 不可用分支。
- 结论：所有 `targetEnvironment(simulator)` 守卫仅在模拟器生效，真机仍走原 `isAvailable()` 判定，真机行为不受影响。模拟器「未检测到 iCloud」红字为预期。

- 根因：模拟器 `simulateFree=true` 把付费分支堵死，完全依赖 `cfg.freeQuotaEnabled`。云端 `aia_config.global` 文档**原本缺 `freeQuotaEnabled` 字段**（仅 `agentEnabled`/`modelProvider`/`visionModelProvider`）→ `GlobalConfigStore` 默认 `false` → 两分支都不满足 → 不显示。
- 修复：CloudBase 控制台「环境默认数据库」`aia_config` 的 `global` 文档用「+ 添加字段」补 `freeQuotaEnabled: Bool = true` 和 `freeQuotaPerMonth: Number = 30`（注意类型别选成 string，要 Bool/Number）。模拟器冷启后 `fetchConfig()` 拉到即显示。
- 配套：aia-sync 当日改了 `entitlement.js`，重新打包 `aia-sync-20260805.zip` 并部署（HTTP 触发 `/sync`，集成响应开关同 `/recognize`）。
- 结论：免费版体验模式下的「本月福利」卡**唯一来源是云端 `freeQuotaEnabled` 开关**，与登录账号/真机付费状态无关。

## 测试账号白名单（aia_testers）排查 + 云函数容错修复（2026-08-05）
- 现象：开发者中心→测试账号管理点 + 新增（账号 ID=`apple_000466...`），日志报 `document.get:fail ... tester_userId_apple_000466... does not exist`，列表恒空。
- 根因链：①云端 `aia_testers` 集合根本没建 → `listTesters` 报 `collection not exists`（ResourceNotFound）；②建集合后新增仍失败，因 `entitlement.js` 的 `upsertTester` 先 `db.collection(...).doc(docId).get()`，当该 docId **不存在**时 CloudBase 在 ADMINONLY 权限下 `doc().get()` 直接抛异常，被外层 catch 当失败返回 "does not exist"，永远走不到「不存在则 set 新建」分支。
- 修复（`云函数/aia-sync/entitlement.js` `upsertTester`）：把 `doc(docId).get()` 包进内层 try/catch，异常即视为 `existData=null`，继续走 `set` 新建。已重新打包 `aia-sync-20260805.zip` 并部署（HTTP `/sync`，集成响应开关同 `/recognize`）。
- App 端配合改动：`TesterManagerView.swift` `list()` 失败时把后端 `error` 透出（"拉取失败: xxx"）；`DeveloperCenterView.swift` 测试账号管理入口图标 `person.2.badge.shield`→`person.badge.key.fill`（语义=受控账号）。两处 `read_lints` 0 错误。
- 权限结论：`aia_testers` 集合权限用 **无权限 [ADMINONLY]**（只有云函数/管理员能读写，前端不可访问）；**不要**选 ADMINWRITE（用户可读全部数据）。容错修复后 ADMINONLY 下新增正常。
- 验证：重新部署后 + 新增日志返回 `{"ok":true,"items":[{"_id":"tester_userId_apple_000466...","kind":"tester","enabled":true,...}]}`，白名单生效。
- 账号 ID 含义：设置页「同步账号」复制的值；Apple 登录为 `apple_000466.<uuid>.<suffix>` 格式（= `aia.userId`，即 `CloudSyncManager.userId` 的已登录分支）。白名单精确比对 `_id = "tester_" + idType + "_" + idValue`。
